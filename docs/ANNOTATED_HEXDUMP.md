# Annotated hexdump of one complete exchange

Generated by `build/hexdump` from the actual protocol encoder. The three frames below form one complete request and response body exchange.

## Request: `GET /index.html`

```text
00000000  42 4e 01 01 01 00 00 01 00 00 00 2b 1f 1a 52 2a  |BN.........+..R*|
00000010  01 00 0b 2f 69 6e 64 65 78 2e 68 74 6d 6c 02 04  |.../index.html..|
00000020  68 6f 73 74 00 09 6c 6f 63 61 6c 68 6f 73 74 06  |host..localhost.|
00000030  61 63 63 65 70 74 00 03 2a 2f 2a                 |accept..*/*|
```

**Bytes 0–15: frame header**

- `42 4e` = magic `BN`.
- `01` = protocol version 1.
- `01` = frame type REQUEST.
- `01` = END_STREAM flag; this GET has no request body.
- `00` = reserved byte.
- `00 01` = stream ID 1.
- `00 00 00 2b` = payload length 43 bytes.
- `1f 1a 52 2a` = CRC-32 of the 43-byte payload.

**Bytes 16 onward: request payload**

- `01` = method GET.
- `00 0b` = path length 11.
- `2f 69 6e 64 65 78 2e 68 74 6d 6c` = `/index.html`.
- `02` = two headers.
- `04` + `68 6f 73 74` = header name `host`.
- `00 09` + `6c 6f 63 61 6c 68 6f 73 74` = value `localhost`.
- `06` + `61 63 63 65 70 74` = header name `accept`.
- `00 03` + `2a 2f 2a` = value `*/*`.
